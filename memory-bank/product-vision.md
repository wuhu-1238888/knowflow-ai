# 产品愿景(Product Vision)

> 版本:v0.1 | 最后更新:2026-09-08
> 对应阶段:Stage 01 项目定义

## 定位一句话

KnowFlow AI 是面向企业新员工的 AI 知识助手:用 RAG(向量 + 关键词混合检索 + 重排)从企业知识库中给出**带来源引用**的准确回答,知识库没有答案时**明确拒答**,并附带**可复现的检索质量实测数据**——让企业用户更快、更准确、更可信地获取内部知识。

## 核心问题

- **现象**:企业知识客观存在但不可达。新员工入职期知识获取依赖"翻共享盘 + 反复问人",耗时且怕打扰;知识分散在制度、IT、产品、技术 SOP 等多种文档里,内部搜索要么关键词对不上、要么结果无关。
- **信任缺口**:直接拿大模型回答企业内部问题有幻觉风险——回答没有来源不敢信;知识库里本来就没有答案时,用户分不清"没有答案"和"没搜到"。
- **为什么是现在**:本地开源中文 Embedding/Rerank 模型已成熟,混合检索 + 重排 + 引用 + 拒答的可信 RAG 链路可以零 API 成本搭建并**用固定评测集实测验证**;对企业知识场景,"可验证的检索质量"正从营销话术变成可实现的工程标准。

## 成功标准(可度量)

1. **评测达标**:最小评测集 14 例(7 类场景,定义与标注见 `docs/demo-data/evaluation/cases.yaml`)在 Hybrid+Rerank 模式下,检索层与生成层指标全部达到 `docs/evaluation-plan.md` 定义的阈值;阈值与达标线于 Stage 08 定稿后回填于此。**所有数值只来自实测 run JSON,禁止虚构或预估。**
2. **演示闭环**:核心 demo 闭环 ≤ 5 分钟走通——打开产品 → 上传一篇文档 → 提问 → 获得带引用回答 → 点开来源核对原文 → 演示一次"知识库无答案"的拒答,全程计时 ≤ 5 分钟。

## 边界

### 做什么(4 条)

1. RAG 知识问答:文档上传与解析 → 分块索引 → 三模式检索(Vector / Hybrid / Hybrid+Rerank)可切换 → LLM 生成回答。
2. Trust 机制:每条回答带来源引用(Citation)并可点开核对源文档与原文片段;知识库无答案时明确拒答;多来源口径矛盾时并列呈现双方依据、不替用户选边。
3. 检索质量实证:固定评测集(7 类场景 14 例)对三种检索链路做同条件对比实验,输出可复现的指标矩阵。
4. NovaTech 演示知识库:虚构 SaaS 软件公司的合成演示文档(制度/IT/产品/技术 SOP 等),全部文档标注 `synthetic: true`,仅用于演示与评测。

### 明确不做什么(带理由)

| 不做的事 | 理由 |
| --- | --- |
| Multi-Tenant 多租户 | MVP 边界:单租户演示足够,作品集展示检索质量而非租户隔离;记录 Future Expansion |
| 企业级 RBAC/SSO 权限体系 | MVP 边界:虚构单租户数据无真实组织,不做权限空转;记录 Future Expansion |
| 复杂组织架构与审批流 | MVP 边界:无真实决策链,审批流无对象;记录 Future Expansion |
| Agent / Multi-Agent 自主任务 | MVP 边界:核心价值是检索质量与可信回答,不是自主规划;记录 Future Expansion |
| Memory 会话记忆 | MVP 边界:无状态问答即可验证核心闭环;记录 Future Expansion |
| Tool Calling 工具调用 | MVP 边界:产品无外部动作面;记录 Future Expansion |
| 多模态 RAG / OCR | MVP 边界:演示文档限定文本型(PDF/Markdown/DOCX/HTML/TXT),图片/扫描件不支持;记录 Future Expansion |
| 自训练 Embedding / Reranker | MVP 边界:现成开源模型(bge 系列)足够;记录 Future Expansion |
| 企业系统集成(IM/网盘/CRM 等) | MVP 边界:零集成保证"克隆即可跑";记录 Future Expansion |
| 接入真实企业数据 | 本作品集使用明确标注 synthetic 的虚构企业 NovaTech 数据,任何场合不描述为真实企业客户或真实商业项目 |
| 复用 CareerOS-AI 产品逻辑/代码/数据 | 项目隔离红线:KnowFlow AI 独立实现,仅复用通用工作流与模板 |

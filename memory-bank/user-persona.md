# 用户画像(User Persona)

> 版本:v0.1 | 最后更新:2026-09-08
> 对应阶段:Stage 02 用户与场景

ToB 项目:覆盖购买者/决策者/使用者三类,痛点互不相同。NovaTech 为约 300 人的虚构 SaaS 软件公司(核心产品:NovaFlow 云平台),决策链短,知识管理负责人身兼购买者与决策者。

## Persona 1:林晓(使用者 · MVP 主场景)

- **画像**:26 岁,后端工程师,入职 NovaTech 第 1–2 周。对公司组织、制度、内部产品几乎一无所知,有一个带教导师但不愿频繁打扰。
- **使用场景**:入职第一天配开发环境与账号;第 3 天报销入职路费;第 5 天连不上 VPN 影响远程办公;第 2 周接手第一个需求,要理解 NovaFlow 平台架构与内部术语。
- **核心痛点**(按痛苦程度排序):
  1. 不知道去哪找:知识分散在共享盘、Wiki、IM 群文件里,连"该搜哪个目录"都不清楚;
  2. 怕问人:频繁请教导师有心理负担,问多了显得不专业;
  3. 文档看不懂:内部文档满是缩写与平台术语,新人读不懂也没人翻译。
- **当前替代方案**:共享盘里翻 PDF、问导师/同事、内网 Wiki 硬搜(关键词对不上就搜不到)。
- **放弃原因假设**:连续两次搜到的答案答非所问;回答没有来源,不敢信也不敢用;最后退回"直接问人"。

## Persona 2:陈立(购买者 + 决策者)

- **画像**:42 岁,NovaTech 知识管理负责人,兼 IT 负责人。负责内部知识库建设与 IT 支持团队,向上汇报"知识资产价值"。
- **使用场景**:季度复盘时评估知识库效果;新员工集中入职季关注入职效率;审批知识管理工具的采购与预算。
- **核心痛点**(按痛苦程度排序):
  1. 专家时间被重复问题占用:资深员工反复回答同类问题,产出受损;
  2. 旧答案仍在被引用:制度文档更新后,旧的 PDF 副本还在被传播与引用,埋下口径混乱;
  3. 知识库效果无法衡量:"大家都不看文档"还是"文档查不到",拿不出数据。
- **当前替代方案**:Wiki + 共享盘 + 企业 IM 里问专家,人工维持秩序。
- **放弃原因假设**:AI 给出过一次错误答案引发信任事故;系统接入与维护成本高于"维持现状"。

## Persona 3:王工(使用者 · 辅助场景)

- **画像**:31 岁,IT 服务台支持工程师,每天处理内部工单。对常见问题烂熟于心,但新发布的系统与流程更新快,记忆容易过期。
- **使用场景**:周一高峰/新人入职季,大量重复工单(账号开通、VPN、邮箱配置);遇到少见问题时需要翻 SOP 确认准确步骤再回复。
- **核心痛点**(按痛苦程度排序):
  1. 重复回答消耗大量时间,高峰期排队工单积压;
  2. 找 SOP 耗时:记得有这份文档但不记得在哪、具体步骤记不准;
  3. 回复口径要求准确:发给同事的每一步操作都要有据可依,不能凭印象。
- **当前替代方案**:个人笔记 + 翻 SOP 文档 + 群聊快捷回复模板。
- **放弃原因假设**:检索不到可操作的具体步骤;答案无来源,不敢直接发给同事,仍需自己二次确认。

## 目标用户一句话确认

> 我们要服务的,是**NovaTech 新入职员工**(主场景)与**IT 服务台工程师**(辅助场景);购买与决策由知识管理负责人拍板。(由人确认)

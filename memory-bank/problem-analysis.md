# 问题与需求分析(Problem Analysis)

> 版本:v0.1 | 最后更新:2026-09-08
> 对应阶段:Stage 03 问题与需求分析

## 核心问题定义

**一句话**:企业知识客观存在但不可达——新员工无法在合理时间内、以可信方式自助获取准确知识。

- **现状**:知识分散在共享盘、Wiki、IM 群文件中,跨制度/IT/产品/技术 SOP 多种文档类型;内部搜索依赖关键词精确匹配,换一种说法就搜不到;大模型直答有幻觉风险,回答没有来源不敢信;知识库里本来没有答案时,用户分不清"没有答案"和"没搜到"。
- **影响**:新员工入职期知识获取高度依赖问人,学习效率低且心理负担重;IT 服务台重复回答高频问题;专家时间被重复问题占用;知识库效果无法衡量,旧文档被持续误引用。
- **证据来源**:本项目为虚构企业(NovaTech)演示场景,证据来自 Stage 02 persona 的场景推演与痛点排序,**无真实用户访谈数据**,不对外声称真实调研结论。

## 子问题拆解

| 子问题 | 影响人群 | 痛点证据 | 严重度(高/中/低) |
| --- | --- | --- | --- |
| 1. 知识分散:同一主题散落多处、多格式,不知去哪找 | 新员工、IT 服务台 | 林晓痛点 1"不知道去哪找";王工痛点 2"记得有但不记得在哪" | 高 |
| 2. 检索不精准:关键词匹配不到语义等价问题,结果无关 | 所有使用者 | 林晓"内网 Wiki 硬搜搜不到";王工"检索不到可操作步骤" | 高 |
| 3. 回答不可信:无来源、有幻觉风险,不敢用 | 所有使用者、决策者 | 林晓"没来源不敢信";陈立"错误答案引发信任事故" | 高 |
| 4. 知识库空白无提示:分不清"没有答案"与"没搜到" | 所有使用者 | 反复尝试无果后放弃,退回问人(放弃原因假设) | 高 |
| 5. 文档冲突:新旧版本并存、口径不一,旧答案仍被引用 | 新员工、IT 服务台、决策者 | 陈立痛点 2"旧 PDF 副本仍在传播被引用" | 中 |
| 6. 专家被重复打扰:重复问题消耗专家时间 | 专家、管理层 | 陈立痛点 1;王工痛点 1"高峰期重复工单积压" | 中 |

## P0 闭环叙述

> 打开产品 → 上传一篇文档 → 提问 → 获得带来源引用的回答 → 点开来源核对原文 → 演示一次"知识库无答案"的拒答。全程 ≤ 5 分钟,对应成功标准 2。

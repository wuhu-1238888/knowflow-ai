# KnowFlow AI 演示脚本(3.4.1 定稿)

> 版本:v1.0 | 2026-09-10
> 用途:作品集 / 面试现场演示;口径按 CLAUDE.md 全局验收锚点 2「核心 demo 闭环 ≤ 5 分钟」——打开产品 → 上传一篇文档 → 提问 → 获得带引用回答 → 点开来源核对 → 演示一次拒答,全程计时。
> **诚信口径(演示前对观众说明,必说)**:本产品演示数据全部为虚构企业 NovaTech 的合成数据(每篇标注 synthetic: true),不指向任何真实企业;用于展示 RAG 检索质量与可信问答能力。

## 0. 环境与准备阶段(不计时,强烈推荐 2 分钟)

1. 启动:`npm run dev`(前端 http://localhost:3001 + 后端 8000;详见 README 快速开始)。
2. **预热(推荐)**:浏览器打开 http://localhost:3001,在知识问答页提问「年假有几天?」并等待回答完成,然后刷新页面回到初始态。这一步把本地检索模型(bge-m3 嵌入 + bge-reranker 重排)加载到内存,正式演示时每问约 30 秒(耗时主体是 reranker CPU 推理 24 个候选;默认 LLM_PROVIDER=mock 生成瞬时、无网络调用)。
   - 不预热的代价(2026-09-10 实测):首次上传需约 61 秒(embedding 冷启动)、首个问题约 60 秒(本地模型加载 ~30s + 检索推理 ~30s,预算口径)——仍能在 5 分钟内完成,但余量小。
3. 确认文档库为 20 篇基线(演示上传后需清理,见第 6 步)。
4. 准备上传文件:`docs/demo-data/upload/doc-cafe-01.md`(NovaTech 办公室咖啡吧使用规范;合成数据,不在种子库中)。

## 1. 正式演示六步(计时开始)

> 每步含:动作 → 台词(可照念)→ 预期结果 → 时间预算(热态实测值;冷态最坏值见 §3)。

### 步骤 1 打开产品(预算 <5 秒)

- 动作:浏览器打开 http://localhost:3001,展示侧栏四页(知识问答 / 文档库 / 评测 / 关于)。
- 台词:「这是 KnowFlow AI,企业 AI 知识助手——用 RAG 检索 + 大模型,给带来源引用的回答,知识库没有答案时明确拒答。演示数据是虚构企业 NovaTech 的合成数据。」
- 预期:页面 200,无加载卡顿。

### 步骤 2 上传一篇文档(预算:热态 ~5 秒 + 讲解 30 秒;冷态 ~61 秒)

- 动作:进入「文档库」页 → 点「上传文档」→ 选择 `docs/demo-data/upload/doc-cafe-01.md`。
- 台词:「先上传一篇新文档——《办公室咖啡吧使用规范》。上传后系统会解析、分块、向量化并建立关键词倒排索引。」
- 预期:列表顶部出现新行,状态徽标「解析中」→ 变为「已索引」(解析期间正好讲原理:分块 → bge-m3 向量化 → BM25 全文倒排)。
- 注意:**等状态徽标变为「已索引」再进入下一步**;解析失败(不应出现)则按 §3 应急。

### 步骤 3 提问,获得带引用回答(预算:热态 ~35 秒;冷态 ~90 秒)

- 动作:进入「知识问答」页 → 提问「办公室咖啡吧的咖啡可以免费喝吗?」→ 回车。
- 台词:「问一个只存在于刚上传文档里的问题。回答必须引用企业知识库,并给出可点开的来源依据。」
- 预期:「AI 生成中」胶囊 → 回答呈现,含依据与来源(n):文档标题「NovaTech 办公室咖啡吧使用规范」、来源徽标、相关度分数;正文引用 [n] 编号与依据条目对应。
- 实测口径(2026-09-10):命中新上传文档,相关度 0.99,回答内容与文档一致。

### 步骤 4 点开来源核对原文(预算 ~20 秒)

- 动作:点回答下方第一条依据的「查看原文」→ 右侧滑出来源抽屉。
- 台词:「每条回答都能回溯。这里展示原始 chunk 全文、来源文档与检索相关度——用户可以自己核对,不靠模型『声称』。」
- 预期:抽屉内原文包含回答所述内容(如「使用自带杯取用咖啡,每杯奖励 1 元环保积分」);Esc 或点遮罩关闭。
- 加分项:顺带点开「文档库」中该文档,展示它就是刚才上传的那篇。

### 步骤 5 演示一次拒答(预算 ~35 秒)

- 动作:提问「公司有宠物寄养福利吗?」。
- 台词:「知识库没有答案时,产品明确拒答,而不是编造。」
- 预期:中性灰拒答卡「知识库中未找到答案」+「依据 0 条」+「联系知识库管理员」建议;无编造内容。
- 实测口径(2026-09-10):no_answer=True,confidence 0.0015(该问题来自评测集 C11,稳定复现)。

### 步骤 6 收尾与清理(计时结束,约 15 秒)

- 动作:回到「文档库」→ 删除刚才上传的咖啡吧文档(危险操作二次确认)→ 恢复 20 篇基线。
- 台词:「演示结束。文档库恢复到演示前状态。」
- 可选收尾:进入「评测」页展示三模式指标矩阵(注意:这不在 5 分钟闭环口径内,可作附加环节);进入「关于」页展示定位与 synthetic 声明。

## 3. 应急预案

- **首问/上传过慢(>90s)**:属模型冷启动,台词化解:「第一次调用需要加载本地检索模型,稍等」;不中断计时,冷态总预算仍 ≤5 分钟。若配置了 DeepSeek 且现场网络差导致其超时:快速重问一次;仍失败则说明「演示环境网络限制」并停止,不伪装成功(默认 Mock 无网络依赖)。
- **上传解析失败(状态变红色)**:文档库行内点「重建索引」重试一次;仍失败则跳过上传步骤,改用库内已有问题(「年假有几天?」)演示提问→引用→拒答,并在演示后如实说明。
- **回答未命中新文档**:说明检索未生效,不演示「命中新文档」话术;如实说明并继续步骤 4/5(引用核对与拒答不依赖该步)。
- **拒答不稳定(模型答了)**:追加一句「知识库没有相关内容时,产品必须拒答」——当前版本以阈值 + 规则管线判定(评测集 14 例中无答案/拒答类全部实测达标);现场不隐瞒偶发。
- **演示前库状态异常(≠20 篇)**:以「文档库」页实际列表为准,先删除多余文档再开始;不影响闭环口径。

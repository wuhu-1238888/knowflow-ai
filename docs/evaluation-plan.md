> 对应:Stage 07 起草 / Stage 08 定稿

**定稿记录(2026-09-08,人拍板)**:评测集 14 例(7 类场景)已人工标注(cases.yaml);阈值冻结——检索层 Hybrid+Rerank 模式 Hit@5 ≥ 11/12、MRR ≥ 0.8;生成层各达标线见第 2 节。按诚信规则,定稿后不可单方修改阈值;实测不达标时调整管线/参数,不改阈值。

## 1. 评测集(14 例 / 7 类场景)

夹具位置:`docs/demo-data/evaluation/cases.yaml`(入库);文档集:`docs/demo-data/documents/`(20 篇 NovaTech 虚构文档)。

| 类别 | 例数 | 检验目标 |
| --- | --- | --- |
| 1 精确关键词检索 | 2 | BM25 对文档特有词的价值 |
| 2 语义检索 | 2 | 向量检索对换说法/同义词的价值 |
| 3 多文档问题 | 2 | top-k 与多引用(答案跨 2+ 文档) |
| 4 相似文档干扰 | 2 | 排序/Rerank 排除干扰文档的能力 |
| 5 专业术语 | 2 | 术语表命中与内部缩写理解 |
| 6 知识库无答案 | 2 | 拒答鲁棒性(1 完全无关 + 1 表面相关) |
| 7 文档冲突 | 2 | 新旧版口径矛盾 → 并列呈现 |

样例格式(cases.yaml):

```yaml
- id: C01
  category: 精确关键词检索
  query: "年假有几天?"
  expected_behavior: answer          # answer | refuse | conflict
  expected_doc_ids: [doc-hr-05]      # 期望命中文档(至少 doc 级;chunk 级标注期补充)
  expected_chunk_ids: []             # 标注期填写
  expected_answer_points:            # 人工标注的答案要点
    - "年假 10 天"
  annotated_by: ""                   # 人工标注签字
```

标注要求(SOP/04 L5):**人手工出题/审题并逐例标注签字**;先定文档集、后出题标注;文档集改动 → 受影响样例重新标注并记录。无答案类(2 例)不参与检索层命中指标;冲突类检索命中定义 = top-k 含任一期望 doc。

## 2. 指标与阈值

### 检索层(12 例有答案样例)

| 指标 | 定义 | 达标线(Hybrid+Rerank 模式) |
| --- | --- | --- |
| Hit@5 | 期望 doc 是否出现在 top-5;冲突类 = 命中任一期望 doc | **≥ 11/12** |
| MRR | 期望 doc 排名倒数的均值 | **≥ 0.8** |

- Vector-only 与 Hybrid 模式为对照组:**只记录数值展示增益,不设达标线**。
- nDCG@5 不做:需人工分级相关性标注,14 例规模下 Hit@5+MRR 足够(记录为有意不做)。

### 生成层(14 例全量,人工判定为金标准)

| 指标 | 达标线 |
| --- | --- |
| 答案要点覆盖率 | ≥ 90%(期望要点命中数/总数,人工核对) |
| 幻觉断言 | 14 例合计 **0 例**(回答中无法在任何被检索 chunk 找到依据的断言) |
| Citation 正确性 | 每条引用指向被检索 chunk 且与答案要点对应;**错误引用 = 失败例** |
| 拒答正确率 | 无答案 2/2 拒答;其余 12 例 0 误拒 |
| 冲突检测 | 冲突类 2/2 检出并并列呈现双方来源 |

### LLM-as-judge 定位

适用 = 大规模粗筛;局限 = 与回答同源模型的自我偏好、中文场景方差、稳定性。**本项目 14 例规模小:人工判定为金标准,LLM-judge 仅作辅助**,两者判定不一致率必须记录在报告中。

## 3. 三模式对比实验协议

1. **环境冻结**:记录 embedding/reranker/LLM 版本与全部参数 → `params_hash`;文档集与评测集以 git commit 锁定(结果文件记录 doc_commit)。
2. **检索层实验**:一条命令对 12 例跑 `mode = vector / hybrid / hybrid_rerank` → 每例 top-k 排名落盘 `docs/eval-results/run-<timestamp>-<mode>.json` → 指标脚本算 Hit@5/MRR → 输出 mode×category 矩阵。
3. **生成层实验**:三模式分别跑 14 例全链路(同一 LLM provider;Mock 阶段先跑,真实 Key 到位后重跑同一套)→ 人工核对表(要点/幻觉/引用/拒答/冲突)记录在案。
4. **增益计算**:ΔHit@5 与 ΔMRR 数值(Vector→Hybrid、Hybrid→Hybrid+Rerank)写入 `docs/evaluation-report.md`,每格数值标注 run-id。

## 4. 诚信规则(定稿后写死,不可单方修改)

1. 阈值定稿后**不可单方修改**;实测不达标 → **调整管线/参数,不改阈值**;确需改阈值 = 人拍板 + 记录理由 + 重跑全套。
2. 评测报告只引用 run JSON 实测值,**禁止手填/预估数字**;数值改动必须重跑。
3. 同参数重跑数值一致(可复现)是 FR-08 的验收口径。
4. 文档集/评测集/结果 JSON 全部入库;运行态数据(runtime/、向量库文件)不入库。

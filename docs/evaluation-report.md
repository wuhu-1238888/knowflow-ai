### 2.4 性能 NFR 实测(诚实记录:检索 < 3s 不达标)

- **检索接口耗时**(2026-09-10 实测,截断回退后代码,curl 计时):hybrid_rerank 热态每问
  35.4 / 31.0 / 30.9 s,拒答一问 30.7 s。耗时构成:reranker CPU 推理 24 个候选**全文本**(~28s)+
  embedding / BM25(~1–2s)+ Mock LLM(≈0s,确定性摘句)。NFR「检索接口 < 3s」**超标约 10 倍,不达标**。
- **截断优化实验(负结果,已回退)**:将 rerank 输入截断到 200 字,热态每问降至 ~16s,但
  MRR 0.9583 → **0.8542**(run-eece000b19c7,115419Z 批次:逐例 C04 排名 1→4、C08 1→2,该两例的
  区分信息位于 chunk 300 字之后)。探测表明能保住指标的 500 字截断相对全文本仅快 ~10%,
  无实际收益 → 人拍板回退(commit `18a09ef`),检索性能优化另立任务
  (候选数 CANDIDATE_FACTOR 3→2 / ONNX 加速等,均须人拍板 + 重跑评测)。
  > 参数冻结盲点(如实记录):截断实验批次(115419Z)与基线同 params_hash——当时截断常量未纳入
  > params_hash 载荷;该常量已随回退删除,当前代码无此盲点。
- **评测全量时长**:121215Z 批次 12:12:15Z 启动 → 三模式 run JSON 落盘完成 20:20:17(+08:00),
  实测 **8 分 2 秒 < 10 分钟 NFR** ✓(余量约 2 分钟,主要耗时在 hybrid_rerank 单模式 ~7.3 分钟)。
- **生成接口 NFR(< 15s)**:Mock 下 LLM 段 ≈0s;DeepSeek 真实调用待 Key 写入后实测(§3.2)。

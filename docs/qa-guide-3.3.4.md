# 评测页(3.3.4)测试验收指引

> 版本:v0.1 | 2026-09-10
> 适用:任务 3.3.4 评测页全量(运行评测按钮 / 运行历史 / per-case 明细 / 动态数据源 / 页头「检索评测」)L4 手工走查与切片验收
> 口径:所有预期值来自实测(后端 pytest 149 例、前端 vitest 125 例、双链路 curl 实测),不虚构;验收结论以本指引亲测为准。

## 0. 环境与前置(约 1 分钟)

- 前端 3001、后端 8000 均已运行。检查:`curl http://127.0.0.1:8000/health` → `{"status":"ok"}`;浏览器打开 http://localhost:3001/eval
- 页头标题为「**检索评测**」(3.3.4 人拍板口径,原「评测」已改)
- 数据库已有一批含逐例明细的实测批次(2026-09-09T16:45:08Z,三模式 Hit@5 均 12/12;MRR 0.9583/0.9028/0.9583)与历史 CLI 批次(无逐例明细)

## 1. 评测矩阵检查(动态数据源,约 3 分钟)

1. **矩阵自动呈现**:打开页面即见「评测矩阵」区,展示最新完成批次三行(vector/hybrid/hybrid_rerank),无任何硬编码数字(整页数字只来自 /api/eval/runs)
2. **场景列**:7 类场景列来自逐例明细(假期制度 / 报销流程 / 精确关键词检索等);每格为「命中/总数」如 `1/1`、`0/1`;refuse 类(不参与指标)不占列
3. **总指标列**:Hit@5 三行 `12/12`、MRR 0.9583 / 0.9028 / 0.9583(mono);Recall@K/Precision@K/平均延迟三列显式「暂无数据」(3 行 × 3 列 = 9 格)
4. **混合+重排行**:surface-2 底 + 「当前默认」徽标;其余两行 hover 高亮
5. **数据来源页脚**:「数据来源:run run-xxx · params_hash xxx · doc_commit xxx · YYYY-MM-DD HH:MM 实测」+「暂无数据」说明 caption
6. **诚实说明**:若最新批次为历史 CLI 批次(无逐例明细),矩阵仅显示总指标列 + caption「本批次未存逐例明细…重新运行评测可生成逐例明细」,不虚构场景列

## 2. 运行评测检查(约 8–10 分钟,真实评测约 8 分钟)

1. 点击右上角 **primary「运行评测」**(本页唯一 primary)→ 按钮变「评测运行中…」(disabled + 按钮内 16px 细环旋转,内容区无其他旋转加载)
2. 矩阵区立即变**骨架脉动** + caption「评测运行中,预计需要数分钟;本页每 5 秒自动刷新状态…」
3. 运行历史区出现三条新记录(本批):模式 + 「运行中」徽标(info)+「计算中…」
4. **并发控制**:运行期间再点「运行评测」不可点(按钮禁用);若用 curl 再发 `POST /api/eval/run` → 409「已有评测正在运行,请等待完成」
5. **轮询自动刷新**:不做任何操作,约 5 秒一次自动刷新;约 8 分钟后三条记录逐个变「已完成」,矩阵自动从骨架切换为最新批次结果;按钮恢复「运行评测」
6. 若中途停止后端再启动(模拟中断):遗留 running 行超过 30 分钟后,下一次点击「运行评测」→ 先将其标记「失败」并放行新批次(行内显示「运行中断(超时未完成)」)

## 3. 运行历史与逐例明细检查(约 3 分钟)

1. **行信息**:每行 = 模式名(向量搜索(Vector)/混合搜索(Hybrid)/混合+重排(Hybrid + Rerank))+ 状态徽标(已完成 success / 运行中 info / 失败 danger)+ 时间(YYYY-MM-DD HH:MM)+ `params xxxxxxxx`(8 位截断)+ `commit xxxxxxx` + Hit@5/MRR(mono)+「展开」
2. **展开逐例明细**:点行 → 下方出现明细表:用例(C01…C14,mono)/ 类别 / 问题 / 期望行为(应作答/应拒答/应指出冲突)/ 首个期望排名 / 命中(命中·未命中)/ RR(4 位 mono);非指标行(应拒答)排名/命中/RR 显式「—」
3. **跳过例**:如有 skipped 例,底部 caption「跳过 n 例:Cxx(错误原因)」
4. **历史 CLI 批次行**(has_per_case=false,如更早的批次):展开显示「本批(历史 CLI 批次)未存逐例明细,仅展示总指标;重新运行评测可生成逐例明细」——诚实说明,不虚构明细
5. 再点行(或另一行)→ 收起/切换;矩阵批次行展开不重复请求明细(已随矩阵取到)
6. 失败行:状态徽标「失败」(danger)+ 行内红色错误信息(如「运行中断(超时未完成)」/「XxxError: …」)

## 4. 空态与错误态检查(可选,需清库/停后端,约 2 分钟)

1. **空库**:无任何评测记录时,矩阵区显示空态「暂无评测数据」+ 说明「点击右上角「运行评测」…」;运行历史区「暂无运行记录」
2. **停掉 8000** → 刷新评测页 → 矩阵区红色错误文案 +「重试」按钮;重启后点「重试」恢复

## 5. 视觉与无障碍(DesignRules 硬规则)

- **375px 窄屏**:矩阵表格与明细表在容器内横向滚动,页面无整体溢出
- **焦点环**:Tab 走查「运行评测」/「重试」/运行历史行 → 2px 品牌紫描边;行可键盘触发(Enter/Space 展开)
- **动效**:骨架脉动为唯一无限动画;按钮内 16px 细环旋转仅在运行期间出现;无内容区旋转加载
- **每屏一个 primary**:页面只有「运行评测」;「重试」为 secondary;运行历史行为裸按钮(ghost 语义)
- **数字全 mono**:Hit@5、MRR、RR、排名、用例编号、时间;无 emoji 图标
- **容器宽度**:评测页 1152px 居中(2026-09-09 人拍板)

## 6. 判定标准

- **Blocker(不通过,当场修复)**:页面白屏/500/无响应;矩阵数字与 run JSON 不一致;出现硬编码/虚构数字;运行中按钮可重复点击并发启动;点运行评测后无任何反馈;运行完成后矩阵不自动刷新(5 秒轮询失效);展开明细与 run JSON 不一致;历史批次被虚构出明细
- **样式打磨类(记遗留,不阻塞)**:间距/字号微调;轮询频率(5 秒)微调
- **已知非缺陷,勿当 bug 报**:真实评测约需 8 分钟(模型推理,三模式顺序执行);BFF 层将后端 202 归一为 200(成功语义不变);运行历史按批次倒序、批内按 vector→hybrid→hybrid_rerank 固定序;矩阵只展示最新完成批次(历史批次在运行历史中可查);Recall@K/Precision@K/平均延迟尚未纳入评测引擎(显式「暂无数据」,非缺陷)

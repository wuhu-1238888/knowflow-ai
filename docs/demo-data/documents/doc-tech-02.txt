NovaFlow 系统故障排查流程
适用对象:研发与技术支持人员 | 版本:2026-04

一、适用范围

本流程适用于 NovaFlow 平台自身的系统级故障,例如服务不可用、接口超时、数据管道中断、告警计算延迟等。办公设备故障(打印机、投影、电脑)不适用本流程,请直接联系 IT 服务台。

二、排查步骤

1. 确认影响面:先在监控面板查看服务状态与告警,确认受影响的服务与时间段。
2. 定位变更:检查近 24 小时内的发布记录,确认是否与故障时间吻合;多数系统故障由变更引起。
3. 查看日志:按服务名与时间窗口检索日志平台,优先看 ERROR 级别日志与慢查询。
4. 资源检查:确认集群节点、数据库连接池、消息队列堆积是否异常。
5. 止血优先:定位到根因前,可先执行扩容、限流或降级操作控制影响面,止血后再深挖根因。

三、故障分级与响应

- P0(核心链路不可用):立即拉起应急群,平台研发部全员响应;
- P1(部分功能受损):1 小时内响应,值班同事跟进;
- P2(轻微异常):记录工单,1 个工作日内处理。

四、复盘

故障恢复后 3 个工作日内完成复盘,输出根因、改进项与负责人,复盘结论同步到团队周报。

# NovaFlow 发布流程(POD)

> 版本:2026-07 | 适用对象:全体研发人员

## 什么是 POD

POD(Publish On Demand)是 NovaTech 的**按需发布流程**,将发布拆解为「构建 → 灰度 → 全量」三个阶段,发布人凭 CCR 工单按需触发,不再依赖固定周发布窗口。

## 发布步骤

1. **建 CCR**:在项目管理系统中创建代码变更申请单(CCR),关联需求与自测结果;
2. **构建**:合并到主干后触发 CI,构建产物与单测结果自动归档到发布平台;
3. **灰度**:在发布平台选择灰度比例(默认 5%),观察核心指标 30 分钟无异常;
4. **全量**:灰度通过后逐步放量到 100%,发布期间需保持在线;
5. **发布确认**:全量完成后在 CCR 中填写发布结论,关闭工单。

## 新人第一次参与发布的 Checklist

- 确认自己已获得生产环境访问权限(按次授权);
- 提前阅读《代码规范》,确认代码已通过 CI 检查;
- 由带教导师陪同完成首次发布,灰度观察阶段两人共同盯指标;
- 发布遇到任何异常,第一时间回滚并联系平台研发部值班同事。

## 发布红线

- 未经灰度直接全量发布;
- 灰度期间指标异常仍继续放量;
- 发布人失联(发布期间必须保持在线)。
